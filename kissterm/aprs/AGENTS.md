# kissterm/aprs — local contract

APRS is **not a separate protocol stack**. An APRS packet is an AX.25 UI frame
with PID 0xF0 whose information field is APRS text. `kissterm/ax25/` already
decoded the frame; this package only parses and builds that text payload.

Nothing here does I/O or touches a transport. If you need the frame layer, it
is `kissterm/ax25/frame.py` (`AX25Frame`, `UType.UI`, `PID_NO_LAYER3`).

Read this file plus the one source file you are changing.

## File map — which file owns which data type identifier

| Identifier(s) | Meaning | File |
|---|---|---|
| `!` `=` `/` `@` | Position, with/without timestamp | `position.py` |
| `` ` `` `'` | Mic-E current / old | `mice.py` |
| `:` | Message, ack, rej, bulletin | `messages.py` |
| `>` | Status | `messages.py` |
| `;` `)` | Object / item | `messages.py` |
| `_` | Positionless weather | `telemetry.py` |
| `T#` | Telemetry | `telemetry.py` |
| `<` `?` `}` | Capabilities, query, third-party | `parse.py` |

Other files: `types.py` (the dataclasses — imports nothing from this package,
so nothing here can create a cycle), `extensions.py` (shared trailing fields:
`/A=` altitude, PHG, RNG, DFS, comment remainder), `parse.py` (the dispatcher
and `format_packet`), `encode.py` (transmit side).

## The rules that will bite you

1. **Decode is permissive; encode is strict.** `parse_packet` must **never
   raise** on malformed input — a packet off the air can be truncated or
   corrupt in any way, and one bad packet must not take down the pane. On
   failure return an `AprsPacket` with `kind="unparsed"` and the raw info
   preserved. `encode.py` is the opposite: validate and clamp, because a
   malformed packet you *transmit* pollutes the network for everyone.
2. **Mic-E splits one position across two places.** Latitude digits, N/S, the
   longitude offset and E/W live in the *destination callsign*; longitude
   degrees/minutes and course/speed live in the information field. This is why
   `ax25/address.py` keeps raw callsign bytes. Watch the +28/+100 longitude
   offsets and the course/speed wraparound.
3. **Compressed positions are base 91.** `lat = 90 - (sum / 380926)`,
   `lon = -180 + (sum / 190463)`. The cs+T compression-type byte carries either
   course/speed or a pre-calculated range.
4. **ASCII only** in any string this package produces. No emoji.

## Not yet verified — read before trusting this operationally

The Mic-E test fixtures were generated by this package's own inverse encoder.
They prove the decoder is **self-consistent, not correct.** The
destination-callsign polarity for N/S, the longitude offset, E/W, and the 3-bit
message-code table were reconstructed rather than cited from the spec. Mic-E is
the most common position format on 2 m and the most commonly botched decoder.
**Running a real captured Mic-E packet through it is the highest-value open
task in this package.** Compressed-position `{` cs-byte handling (implemented
as a pre-calculated range, not altitude) wants the same treatment.

## Testing

```bash
.venv/bin/python -m pytest tests/unit/test_aprs.py -q
```

Build fixtures as real `AX25Frame`s via the `kissterm.ax25` API, not as raw
bytes — a test that skips the frame layer skips where half the bugs live. Every
new format needs at least one deliberately-malformed case asserting
`kind == "unparsed"` and that nothing raised.
